# 로데오부동산 홈페이지 (단순 구조)

구글시트에 매물을 입력하고 `공개상태`를 **게시**로 바꾸면, 15분 안에 홈페이지에 자동으로 올라갑니다.
PC가 꺼져 있어도 작동합니다. 비용은 무료입니다.

```
구글시트 (매물정보, 공개상태=게시)
  + 구글드라이브 (매물번호 폴더에 사진)
        ↓  GitHub가 15분마다 자동 확인
  홈페이지 자동 생성 → GitHub Pages로 공개
```

---

## 1. 매일 쓰는 방법

| 하고 싶은 일 | 방법 |
|---|---|
| 새 매물 올리기 | ① 시트 `공통매물` 탭에 한 줄 입력 ② 드라이브 매물사진 폴더 안에 **매물번호 이름의 폴더**를 만들고 사진 넣기 ③ `공개상태`를 `게시`로 변경 |
| 가격·내용 수정 | 시트에서 고치면 15분 안에 반영 |
| 사진 교체·추가 | 드라이브 폴더의 사진을 바꾸면 15분 안에 반영 |
| 거래완료·내리기 | `공개상태`를 `거래완료` 또는 `대기`로 변경 → 홈페이지에서 사라짐 |
| 지금 바로 반영 | GitHub 앱 또는 웹 → 저장소 → **Actions** → `매물 홈페이지 업데이트` → **Run workflow** |
| 결과 확인 | 같은 Actions 화면에서 최근 실행을 누르면 "게시 몇 건, 확인이 필요한 항목" 요약이 나옵니다 |

> ⚠ 거래가 끝난 매물은 바로 `거래완료`로 바꿔 주세요. 계약된 매물을 계속 광고하면 부당 표시·광고가 될 수 있습니다.

---

## 2. 구글시트 규칙

- 매물 정보는 **`공통매물`** 탭에 입력합니다. (`건물매매` 같은 다른 탭도 `매물번호` 열이 있으면 비어 있는 항목을 자동으로 채워 씁니다.)
- 첫 줄은 열 이름입니다. **열 이름이 아래 표와 같아야** 홈페이지에 나갑니다. 순서는 상관없습니다.
- **아래 표에 없는 열(집주인 연락처, 상세 주소, 메모 등)은 절대 홈페이지에 나가지 않습니다.** 내부용 정보는 마음 놓고 같은 시트에 적어도 됩니다.

### 필수 열

| 열 이름 | 예시 | 설명 |
|---|---|---|
| 매물번호 | B-0001, A-0012 | 영문-숫자. 드라이브 사진 폴더 이름과 같아야 함 |
| 공개상태 | 게시 / 대기 / 거래완료 | **`게시`만** 홈페이지에 나감 |
| 카테고리 | 아파트, 원룸, 투룸, 오피스텔, 상가, 사무실, 건물매매 | 홈페이지 분류에 사용 |
| 매물명 | 둔산동 남향 30평 아파트 | 홈페이지 제목 |
| 거래유형 | 매매 / 전세 / 월세 | |
| 가격 | 매매 → `매매가(원)` / 전세 → `보증금(원)` / 월세 → `보증금(원)` + `월세(원)` | **원 단위 숫자** (예: 650000000). 쉼표 있어도 됨 |

가격이나 필수 항목이 비어 있으면 그 매물은 **게시되지 않고** 실행 결과에 이유가 표시됩니다.

### 선택 열 (있으면 홈페이지에 표시)

`시도` `시군구` `동/읍면` `공개 주소` · `관리비(원)` `관리비 포함항목` `권리금(원)` · `전용면적(㎡)` `공급면적(㎡)` `대지면적(㎡)` `건축면적(㎡)` `연면적(㎡)` · `해당층` `총 층수` `지하층` `방 수` `욕실 수` `방향` · `사용승인일` `입주가능일` `주차정보` `엘리베이터` `건축물 용도` `구조` · `총 임대보증금(원)` `월 임대수입(원)` · `소개글` `유튜브 링크` `마지막 확인일` `대표사진 파일명`

- **공개 주소**: 홈페이지에 보일 주소. 비워두면 `시도 시군구 동/읍면`만 표시됩니다. 번지까지 공개할지는 직접 판단해 적어주세요.
- **유튜브 링크**: 유튜브에 올린 영상 주소를 넣으면 상세 페이지에 영상이 나옵니다. ('일부 공개'로 올려도 됨)
- **대표사진 파일명**: 첫 화면에 쓸 사진 파일 이름 (예: `03.jpg`). 비우면 이름순 첫 사진.
- 실행 결과에 **"광고 명시 권장 항목 비어 있음"**이 뜨면 총 층수·사용승인일·방향·주차·입주가능일(주거용은 방/욕실 수·관리비) 등을 채워 주세요. 중개대상물 표시·광고 명시사항입니다. (최신 고시 기준은 별도 확인 필요)

## 3. 구글드라이브 사진 규칙

```
매물사진 (← 이 폴더를 서비스 계정에 공유)
 ├─ B-0001            ← 매물번호와 같은 이름 (뒤에 설명 붙여도 됨: "B-0001 탄방동 건물")
 │   ├─ 01.jpg
 │   ├─ 02.jpg        ← 파일 이름 순서 = 홈페이지 사진 순서
 │   └─ 사진/         ← 안에 '사진' 폴더가 있어도 읽음
 └─ A-0012
```

- JPG, PNG 권장. 매물당 최대 30장. 사진은 자동으로 줄여서(웹용) 올라가며 **원본은 그대로** 둡니다.
- 아이폰 HEIC 사진은 변환이 안 될 수 있습니다 → 아이폰 `설정 > 카메라 > 포맷 > 높은 호환성` 으로 찍으면 JPG로 저장됩니다.
- 동영상 파일은 드라이브에서 읽지 않습니다. 유튜브에 올리고 시트에 링크를 넣어 주세요.

## 4. 처음 한 번 설정 (약 20분)

### ① GitHub 준비
1. https://github.com 가입 (이미 있으면 생략)
2. 새 저장소 만들기: 이름 `rodeo-realestate`, **Public** 선택
   - Public이어도 공개되는 것은 홈페이지 코드뿐이고, 시트 내용·키는 공개되지 않습니다.
3. 이 `site` 폴더 안의 파일을 저장소에 올리기 (Claude에 GitHub를 연결하면 Claude가 대신 올릴 수 있음)
   - 직접 올릴 경우: `_github-workflow/publish.yml` 파일은 저장소의 **`.github/workflows/publish.yml`** 위치에 넣어야 자동 실행됩니다. (GitHub 웹에서 Add file → Create new file → 이름에 `.github/workflows/publish.yml` 입력 후 내용 붙여넣기)
4. 저장소 **Settings → Pages → Source: `GitHub Actions`** 선택

### ② 구글 설정
1. 기존 시트 읽기용 **서비스 계정**을 그대로 씁니다. 서비스 계정 이메일(`...@...iam.gserviceaccount.com`)을 확인합니다.
2. 드라이브의 **매물사진 최상위 폴더 → 공유 → 서비스 계정 이메일 추가 → 뷰어**
3. 구글시트도 서비스 계정에 **뷰어**로 공유되어 있는지 확인
4. Google Cloud Console에서 서비스 계정이 속한 프로젝트의 **Google Drive API**, **Google Sheets API**가 "사용"인지 확인

### ③ GitHub에 비밀값 3개 등록
저장소 **Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 값 |
|---|---|
| `GOOGLE_SERVICE_ACCOUNT_JSON` | 서비스 계정 키 JSON 파일 **내용 전체**를 복사해 붙여넣기 |
| `SHEET_ID` | 시트 주소 `docs.google.com/spreadsheets/d/`**`여기부분`**`/edit` |
| `DRIVE_FOLDER_ID` | 매물사진 폴더 주소 `drive.google.com/drive/folders/`**`여기부분`** |

> 🔒 서비스 계정 키는 GitHub 비밀값에만 넣으세요. 채팅·메일·카톡으로 보내지 마세요.

### ④ 첫 실행
**Actions → 매물 홈페이지 업데이트 → Run workflow** → 2~3분 뒤
`https://(GitHub아이디).github.io/rodeo-realestate/` 에서 홈페이지 확인

### ⑤ (선택) 내 도메인 연결
`rodeo부동산.com` 같은 도메인이 있으면 Settings → Pages → Custom domain에 입력하고, 저장소 Settings → Variables에 `SITE_URL`(예: `https://www.도메인.com`)을 등록합니다.

## 5. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| Actions 실행이 빨간 X | 실행을 눌러 오류 문장 확인. `HTTP 403/404` → 시트·폴더를 서비스 계정에 공유했는지, API가 켜져 있는지 |
| 매물이 안 보임 | 실행 요약의 "게시 제외 — 사유" 확인 (가격 누락, 매물번호 형식 등) |
| 사진이 안 보임 | 드라이브 폴더 이름이 매물번호와 같은지, 사진이 JPG/PNG인지 |
| 15분이 지나도 반영 안 됨 | GitHub 예약 실행은 몇 분 늦을 수 있음. 급하면 Run workflow |

## 6. 내 컴퓨터에서 미리보기 (선택)
Node.js 설치 후 이 폴더에서:
```
npm install
npm run sample     ← 가짜 샘플 매물로 생성
npm run serve      ← http://localhost:8080 에서 확인
```

## 7. 파일 구성
| 파일 | 역할 |
|---|---|
| `web/` | 홈페이지 디자인 (기존 로데오 디자인 유지) |
| `scripts/publish.mjs` | 시트·드라이브를 읽어 홈페이지 생성 |
| `scripts/listings.mjs` | 공개 가능한 열 목록(허용 목록)과 게시 조건 |
| `scripts/render.mjs` | 홈/상세 페이지 화면, 중개사무소 정보 |
| `scripts/google.mjs` | 구글 읽기 전용 접속 |
| `_github-workflow/publish.yml` | 15분 자동 실행 설정 (저장소에서는 `.github/workflows/` 위치) |
| `dist/listings.json` (생성물) | 게시 매물 데이터 — 추후 인스타·유튜브·블로그 자동화에 재사용 |

이전 버전(코덱스 작업: Supabase·관리자 화면·Google Cloud Run 구성)은 상위 폴더에 그대로 보존되어 있으며, 새 구조에서는 사용하지 않습니다.
